# サンプルアプリ 要件・ユースケース・機能仕様書

## 1. 文書の目的

本書で制作するサンプルアプリの要件、ユースケース、機能仕様を定義します。本書の執筆およびサンプル実装において、アプリが解決する課題、ユーザーが達成したいこと、画面上の振る舞いを共通認識にすることが目的です。

本書では、アプリを実現するためのフレームワーク、通信方式、データ保存先、外部サービスなどは定義しません。これらは別途、技術要件として検討します。

## 2. アプリの概要

### 2.1 コンセプト

AWSの最新情報を、RPGのクエストを攻略するように学べる個人向けWebアプリを提供します。

ユーザーの関心や学習可能な時間に合わせてAWS関連のニュースを絞り込み、1件のニュースを1つの「クエスト」としてクエストボードへ表示します。ユーザーはクエストの内容を確認し、チャットで質問しながら理解を深め、理解度チェックに回答することでクエストをクリアします。

日々の閲覧数、クリア数、理解度チェックの結果は学習履歴として記録し、週間レポートとして振り返ることができます。

### 2.2 想定ユーザー

- AWSを業務または個人開発で利用している人
- AWSの最新情報を継続的に収集したい人
- 大量のニュースから、自分に関係する情報だけを選びたい人
- ニュースを読んだだけで終わらせず、理解できたか確認したい人

### 2.3 提供価値

- ユーザーの関心に合うAWSニュースを短時間で探せる
- ニュースの概要だけでなく、自分への影響を対話しながら理解できる
- 理解度チェックによって、読んだつもりになることを防げる
- 学習量と理解度を振り返り、次に学ぶ内容を決められる

## 3. 要件

### 3.1 ユーザーの課題

- AWSの更新情報が複数の場所に存在し、継続的に確認する負担が大きい
- 公開される情報量が多く、自分の業務や関心に関係する情報を選びにくい
- ニュースを保存しても、あとで読まないままになりやすい
- ニュースを読んだだけでは、内容を理解できたか判断しにくい
- どの分野をどれだけ学んだか、どの分野の理解が弱いかを振り返りにくい

### 3.2 ユーザー要件

| ID | 要件 |
|---|---|
| UR-01 | ユーザーは、自分の関心と使える時間に合うAWSニュースを探せること |
| UR-02 | ユーザーは、検索結果を優先度の付いたクエストとして確認できること |
| UR-03 | ユーザーは、ニュースの要点と自分への影響を短時間で把握できること |
| UR-04 | ユーザーは、ニュースの詳細を見ながら追加の質問ができること |
| UR-05 | ユーザーは、ニュースを理解できたか問題に回答して確認できること |
| UR-06 | ユーザーは、閲覧数、クリア数、回答数、正解率を週単位で振り返れること |
| UR-07 | ユーザーは、振り返り結果から復習するニュースを探せること |

### 3.3 画面要件

| ID | 要件 |
|---|---|
| SR-01 | 基本画面を、クエストを扱うメイン領域とチャット領域に分けること |
| SR-02 | クエスト詳細の表示中もチャットを操作できること |
| SR-03 | クエスト詳細はメイン領域だけを覆い、チャット領域を覆わないこと |
| SR-04 | チャットで指定した検索条件をメイン領域の表示へ反映できること |
| SR-05 | チャットからメイン領域を変更した場合、何が変更されたか確認できること |
| SR-06 | 理解度チェックと週間レポートをチャット内の専用UIとして表示できること |
| SR-07 | クエストの未着手、閲覧済み、クリア済みを画面上で判別できること |

### 3.4 情報要件

| ID | 要件 |
|---|---|
| IR-01 | 各クエストから、元になったニュースを確認できること |
| IR-02 | ニュースの内容と、アプリが生成した説明を区別できること |
| IR-03 | 検索に適用された条件をユーザーが確認できること |
| IR-04 | 週間レポートの各指標について、何を数えた値か一意に定義すること |
| IR-05 | 再回答によって初回回答の正誤が上書きされないこと |

### 3.5 対象範囲に関する要件

- 個人が自分のAWS学習に利用することを前提とします。
- ニュースの探索、理解、確認、振り返りまでを1つの学習体験として扱います。
- ゲーム風の表現は学習を継続しやすくするために使用しますが、ポイント獲得自体を目的にはしません。
- 検索結果や生成された説明だけで完結させず、元情報を確認できるようにします。
- 利用するライブラリ、フレームワーク、AIモデル、通信方式、外部サービス、保存方式、実行環境は本書の技術選定後に定義します。

## 4. 用語

| 用語 | 定義 |
|---|---|
| ニュース | AWSの新機能、仕様変更、料金変更、事例、技術解説など、学習対象となる情報 |
| クエスト | 1件のニュースを、学習対象として扱える形に整理したもの |
| クエストボード | 複数のクエストを掲示するメイン画面 |
| クエスト詳細 | ニュースの要約や影響など、クエストを攻略するための情報 |
| クエストクリア | 対象ニュースの理解度チェックに回答した状態 |
| 理解度チェック | ニュースの内容を理解できたか確認するための問題 |
| 初回正解率 | 各理解度チェックに対する最初の回答のうち、正解した割合 |
| Generative UI | ユーザーの依頼やニュースの内容に応じて、表示内容や操作方法が動的に構成されるUI |

## 5. 画面構成

アプリの基本画面は、メイン領域とチャット領域の2つで構成します。

| 領域 | 主な役割 |
|---|---|
| メイン領域 | クエストの検索、クエストボードの表示、クエスト詳細の閲覧 |
| チャット領域 | 検索の依頼、クエストへの質問、理解度チェック、週間レポートの表示 |

チャット領域は常に利用できる状態とします。クエスト詳細を表示している間も、ユーザーは詳細を見ながらチャットを続けられます。

### 5.1 クエストボード

- クエストを、掲示板に貼られた依頼書のような形式で表示します。
- 1つのクエストは、1件のニュースに対応します。
- クエストには、少なくともタイトル、対象サービス、概要、重要度、想定学習時間、状態を表示します。
- ユーザーの指定条件に応じて、表示するクエストと表示順を変更します。
- 未着手、閲覧済み、クリア済みを区別して表示します。

### 5.2 クエスト詳細

- クエストを選択すると、メイン領域の上に詳細レイヤーを表示します。
- 詳細レイヤーはメイン領域だけを覆い、チャット領域は覆いません。
- ユーザーは詳細レイヤーを閉じて、元のクエストボードへ戻れます。
- 詳細レイヤーの表示中も、別のクエストへ意図せず切り替わらないものとします。
- チャットでの質問に応じて、表示する詳細項目を追加または更新できます。

クエスト詳細では、ニュースに応じて次の情報を表示します。

- ニュースの要約
- 何が変わったか
- 従来との違い
- 想定される利用場面
- ユーザーへの影響
- 確認すべき事項
- 元情報への参照

すべての項目を常に表示する必要はありません。ニュースの種類とユーザーの質問に応じて、必要な項目を構成します。

### 5.3 チャット

- ユーザーは自然言語でニュース検索や追加説明を依頼できます。
- 現在開いているクエストがある場合、そのクエストを会話の対象として扱います。
- チャットの回答は文章だけでなく、選択肢、問題、グラフなどの操作可能なUIとして表示できます。
- メイン領域の表示を変更する場合は、変更内容が分かる応答をチャットにも表示します。

## 6. ユースケース

### UC-01 条件を指定してニュースを探す

| 項目 | 内容 |
|---|---|
| 目的 | 自分の関心と学習可能な時間に合うAWSニュースを見つける |
| 開始条件 | ユーザーがアプリを利用できる |
| きっかけ | ユーザーがメイン領域またはチャットで検索条件を指定する |
| 基本フロー | アプリが条件を解釈する。ユーザーが解釈結果を確認する。条件に合うニュースをクエストとしてメイン領域へ表示する |
| 代替フロー | 条件が不足している場合、チャットで追加質問する。該当結果がない場合、条件変更の候補を提示する |
| 完了状態 | 指定条件に基づくクエストボードが表示される |

### UC-02 クエストの内容を確認する

| 項目 | 内容 |
|---|---|
| 目的 | ニュースの要点と、自分に関係する変更点を把握する |
| 開始条件 | クエストボードに1件以上のクエストが表示されている |
| きっかけ | ユーザーがクエストを選択する |
| 基本フロー | メイン領域にクエスト詳細を表示する。閲覧済みとして記録する。ユーザーが要約、変更点、影響、元情報を確認する |
| 代替フロー | 詳細情報の一部を生成できない場合、確認できた情報と元情報を表示する |
| 完了状態 | ユーザーがクエストの概要を確認できる |

### UC-03 詳細を見ながら質問する

| 項目 | 内容 |
|---|---|
| 目的 | ニュースの疑問点や、自分の状況への影響を深掘りする |
| 開始条件 | クエスト詳細が表示されている |
| きっかけ | ユーザーがチャットで質問する |
| 基本フロー | アプリが選択中のクエストを前提として回答する。短い説明はチャットへ表示し、比較や影響などはクエスト詳細へ反映する |
| 代替フロー | 対象が曖昧な場合、どのクエストについての質問か確認する |
| 完了状態 | 回答がチャットまたはメイン領域に表示される |

### UC-04 理解度を確認してクエストをクリアする

| 項目 | 内容 |
|---|---|
| 目的 | ニュースの内容を理解できたか確認する |
| 開始条件 | 対象のクエストが選択されている |
| きっかけ | ユーザーが理解度チェックまたはクエストクリアを選択する |
| 基本フロー | チャット内に問題を表示する。ユーザーが回答する。正誤と解説を表示する。ユーザーがクエストをクリアする |
| 代替フロー | 不正解の場合、解説を確認して再回答するか、不正解のまま復習候補としてクリアする |
| 完了状態 | 回答履歴が記録され、クエストがクリア済みになる |

### UC-05 週間の学習状況を振り返る

| 項目 | 内容 |
|---|---|
| 目的 | 学習量、理解度、学習分野の偏りを確認する |
| 開始条件 | ユーザーがチャットを利用できる |
| きっかけ | ユーザーが週間レポートを依頼する |
| 基本フロー | 閲覧数、クリア数、回答数、初回正解率を集計する。数値、グラフ、短い所見をチャット内に表示する |
| 代替フロー | 履歴がない場合、集計対象がないことを表示し、最初のクエスト検索を提案する |
| 完了状態 | ユーザーが1週間の学習状況を確認できる |

### UC-06 振り返りから復習を始める

| 項目 | 内容 |
|---|---|
| 目的 | 理解が不十分だった分野を再度学習する |
| 開始条件 | 週間レポートが表示されている |
| きっかけ | ユーザーが苦手分野の復習を選択する |
| 基本フロー | 初回不正解だったクエストまたは理解が弱い分野を検索条件にする。復習候補でクエストボードを更新する |
| 代替フロー | 復習候補がない場合、新しい分野または未読クエストを提案する |
| 完了状態 | 復習用のクエストボードが表示される |

## 8. 機能仕様

### F-01 ニュース検索条件の指定

#### 概要

ユーザーは、メイン領域またはチャットからニュースの検索条件を指定できます。

#### 指定可能な条件

- 対象期間
- AWSサービス
- 関心領域
- 重要度
- 想定学習時間
- クエストの状態

関心領域には、AI、フロントエンド、セキュリティ、料金、運用などを想定します。

#### 振る舞い

- 条件は複数指定できます。
- 指定されていない条件は、検索対象を制限しません。
- 自然言語で指定された条件は、検索に使用する条件として画面に反映します。
- 条件を解釈できない場合や情報が不足している場合は、チャットで追加の条件を確認します。
- 実行前または実行後に、解釈された検索条件をユーザーが確認できるようにします。

#### 利用例

> 今週のAgentCoreとBedrockから、フロントエンドに影響するものを15分以内で学びたい

この場合、対象期間、AWSサービス、関心領域、想定学習時間を検索条件として扱います。

### F-02 クエストボードの更新

#### 概要

検索条件に合うニュースをクエストとしてメイン領域へ表示します。

#### 振る舞い

- 検索結果をクエストボードへ反映します。
- 検索結果の件数と適用中の主な条件を表示します。
- ユーザーへの影響が大きいと判断したクエストを優先して表示します。
- 検索結果が0件の場合は、該当するクエストがないことを表示します。
- 0件の場合は、期間を広げる、条件を減らすなどの候補を提示します。
- 検索条件を変更した場合は、変更後の結果でクエストボードを更新します。

### F-03 クエスト詳細の表示

#### 概要

選択されたクエストの内容を、メイン領域内の詳細レイヤーへ表示します。

#### 振る舞い

- クエストを選択した時点で、対象クエストを閲覧済みとして記録します。
- 詳細レイヤーには、ニュースの要約と元情報への参照を必ず表示します。
- ニュースの種類に応じて、比較、影響、料金、手順などの表示項目を構成します。
- 詳細レイヤーを表示したまま、チャットへ質問できます。
- チャットの回答が詳細表示に適している場合、詳細レイヤーに新しい表示を追加または既存表示を更新します。
- 詳細レイヤーを閉じた場合、直前の検索条件とクエストボードの状態を維持します。

### F-04 クエストについての対話

#### 概要

ユーザーは、選択中のクエストについて追加の説明を依頼できます。

#### 想定する質問

- 以前との違いを知りたい
- 自分の構成に影響があるか知りたい
- どのような用途で使えるか知りたい
- 料金への影響を知りたい
- 試す場合の手順を知りたい
- より簡単な表現で説明してほしい

#### 振る舞い

- 選択中のクエストを質問の前提として扱います。
- 対象が曖昧な場合は、どのクエストについての質問か確認します。
- 短い説明はチャット内に表示します。
- 比較や複数項目の確認など、広い表示領域が必要な情報はメイン領域の詳細レイヤーへ表示します。
- メイン領域を更新した場合は、その旨と更新内容をチャットで通知します。

### F-05 理解度チェック

#### 概要

クエストの内容に応じた問題をチャット内へ表示し、ユーザーの理解を確認します。

#### 開始方法

- ユーザーが理解度チェックの開始を依頼する
- クエスト詳細の閲覧後、アプリが理解度チェックを提案する
- ユーザーがクエストクリアを選択する

#### 問題形式

- 単一選択問題
- 複数選択問題
- ○×問題

初期リリースでは単一選択問題を基本とします。

#### 振る舞い

- 問題文と選択肢をチャット内の専用UIとして表示します。
- 回答するまで正解を表示しません。
- 回答後に正誤と解説を表示します。
- 不正解の場合は再回答できます。
- 再回答しても、初回回答の結果は上書きしません。
- 回答後は、クエスト詳細へ戻る、追加質問する、クエストをクリアするなどの操作を提示します。

### F-06 クエストクリア

#### 概要

理解度チェックに回答したクエストをクリア状態にします。

#### 振る舞い

- 正解・不正解にかかわらず、理解度チェックへ回答した後にクリアできます。
- 不正解のままクリアする場合は、復習候補として扱います。
- クリア済みクエストは、クエストボード上で未クリアのクエストと区別します。
- クリア済みのクエストも再度開いて復習できます。
- 同じクエストを再度クリアしても、週間のクリア数は重複して加算しません。

### F-07 学習履歴の記録

#### 概要

週間レポートと復習候補の作成に必要な学習履歴を記録します。

#### 記録対象

| 項目 | 記録するタイミング |
|---|---|
| クエストの閲覧 | クエスト詳細を初めて表示したとき |
| 理解度チェックの開始 | 問題を表示したとき |
| 初回回答 | 1回目の回答を送信したとき |
| 再回答 | 2回目以降の回答を送信したとき |
| クエストクリア | クエストをクリア状態にしたとき |

閲覧数とクリア数は、同じクエストについて期間内に1回だけ数えます。

### F-08 週間レポート

#### 概要

ユーザーの依頼に応じて、直近1週間の学習状況をチャット内に表示します。

#### 表示項目

- 閲覧したニュース数
- クリアしたクエスト数
- 理解度チェックの回答数
- 初回正解率
- 日別の学習量
- 学習したAWSサービスまたは関心領域の内訳
- 学習状況に対する短いコメント

#### 指標の定義

| 指標 | 定義 |
|---|---|
| 閲覧したニュース数 | 対象期間中に初めて詳細を開いたクエストの数 |
| クリアしたクエスト数 | 対象期間中に初めてクリアしたクエストの数 |
| 理解度チェックの回答数 | 対象期間中に初回回答を行った問題の数 |
| 初回正解率 | 初回回答で正解した問題数 ÷ 初回回答を行った問題数 |
| 日別の学習量 | 各日に閲覧またはクリアしたクエストの数 |

理解度チェックの回答数が0件の場合、初回正解率は算出せず、未回答であることを表示します。

#### 表示形式

- 主要な数値をまとめたレポートカードをチャット内に表示します。
- 日別の学習量を、小さな棒グラフとして表示します。
- 必要に応じて、AWSサービス別または関心領域別の内訳をグラフとして表示します。
- チャット領域の横幅に収まる情報量とし、詳細な一覧を同時に表示しすぎないものとします。
- 集計結果に応じて、苦手分野や学習の偏りを短い文章で説明します。

#### 週間レポートの自動作成(草案)

> 草案です。優先度は低く、詳細は後で詰めます。上の「概要」は、ユーザーの依頼に応じて、その場で集計する形です。次の内容は、その代わりに、または、それに加えて、検討している形です。

- 毎週、決まった曜日と時刻に、ユーザーごとの週間レポートを自動で作成し、保存します(日曜に作成することを想定します)。
- ユーザーが週間レポートを依頼したときは、保存済みの最新のレポートを、チャット内に表示します。
- 数値(閲覧数、クリア数、回答数、初回正解率、日別の学習量、内訳)は、履歴から、定義どおりに集計します。学習状況に対する短いコメントは、自動で作成します。
- レポートには、復習の候補(初回不正解だったクエスト)を含め、F-09 の復習に使えるようにします。
- 対象期間の履歴がない場合は、レポートを作成しないか、履歴がないことを示すレポートにします(未決)。
- 作成に失敗した場合は、前回のレポートを表示し、更新が遅れていることを示します。

### F-09 振り返りからの再学習

#### 概要

週間レポートから、復習または次週の学習につなげます。

#### 振る舞い

- 初回不正解だったクエストを復習候補として提示します。
- 学習数が少なかった関心領域を次の候補として提示できます。
- ユーザーは、苦手分野の復習、特定サービスの深掘り、次週のクエスト作成を選択できます。
- 選択された内容を検索条件へ反映し、メイン領域のクエストボードを更新します。

### F-10 クエストの自動更新

#### 概要

毎朝、決まった時刻に、AWSの最新情報からクエストを自動で作成します。ユーザーがログインしたときには、すでに最新のクエストが用意されており、待たずにクエストボードを表示できます。

#### 振る舞い

- 毎日、日本時間の午前6時に実行します。
- 対象は、直近2日間に公開されたニュースです。実行は、ユーザーごとに行い、クエストはユーザーごとに保存します。
- 学ぶ価値の高いニュースを、1回の実行につき最大5件、クエストにします。ニュースの選択では、これまでの会話から得たユーザーの関心(好みや、過去に学んだ内容)を優先します。
- クエストの重要度、想定学習時間、要約などは、ニュースの本文に書かれていることだけを根拠に、自動で作成します。
- すでにクエストになっているニュースは、作成しません。保存済みのクエストは、上書きしません。
- 毎朝の実行の内容は、会話の記憶には残しません。
- クエストボードの初回表示では、保存済みのクエストを、そのまま表示します。表示のために、クエストの生成を待たせません。
- ユーザーがチャットで依頼した場合も、その場でクエストを作成して保存できます(F-01、F-02)。
- 保存済みのクエストは、元のニュースが公開情報から外れても、開いて確認できます(F-09 の復習のため)。
- 日次の実行で作成するのは、クエストだけです。ユーザーの学習履歴は変更しません。週間レポートの作成は、別の機能です(F-08)。

#### 失敗したとき

- 一部のユーザーの実行に失敗しても、ほかのユーザーの実行は続けます。
- 実行の失敗は、実行のログに記録します。ユーザーへの通知は、行いません。
- 失敗して更新が遅れても、前回までのクエストを、そのまま表示します。
- 失敗した実行は、自動では再実行しません。

#### 前提と制約

- 取得元は、AWSの最新情報(What's New)です。取得できる期間は、直近1週間ほどです。

## 9. Generative UIの役割

本アプリでは、Generative UIを表示場所によって2種類に分けます。

### 9.1 チャット内で完結するGenerative UI

会話を進めるための小さな操作や、その場で確認できる情報を表示します。

| UI | 用途 |
|---|---|
| 理解度チェック | 問題への回答と解説の確認 |
| 週間レポート | 学習量、正解率、傾向の確認 |
| 条件確認 | 自然言語から解釈された検索条件の確認 |
| 次の操作候補 | 復習、深掘り、次週のクエスト作成などの選択 |

### 9.2 メイン領域を更新するGenerative UI

複数の情報を比較したり、継続的に参照したりするためのUIを表示します。

| UI | 用途 |
|---|---|
| クエスト検索結果 | 条件に合うニュースの一覧と優先順位の確認 |
| クエスト詳細 | ニュースの要約と重要な変更点の確認 |
| 比較表示 | 従来との差分や複数サービスの比較 |
| 影響表示 | ユーザーの関心や利用状況に対する影響の確認 |

チャットで入力された条件や質問がメイン領域に反映された場合、チャットとメイン領域は同じ対象と条件を示す必要があります。

## 10. 主要な利用フロー

### 10.1 ニュースを探して学ぶ

1. ユーザーが検索条件を指定します。
2. アプリが条件を解釈し、クエストボードを更新します。
3. ユーザーがクエストを選択します。
4. メイン領域にクエスト詳細を表示します。
5. ユーザーが詳細を見ながらチャットで質問します。
6. 必要に応じて、メイン領域の詳細表示を更新します。
7. チャット内に理解度チェックを表示します。
8. ユーザーが回答し、解説を確認します。
9. クエストをクリア状態にします。

### 10.2 1週間の学習を振り返る

1. ユーザーが週間レポートを依頼します。
2. チャット内に主要な指標とグラフを表示します。
3. 学習の傾向と復習候補を表示します。
4. ユーザーが次に行う操作を選択します。
5. 選択内容に応じて、メイン領域のクエストボードを更新します。

## 11. 例外時の振る舞い

| 状況 | 振る舞い |
|---|---|
| 検索結果がない | 0件であることと、条件を変更する候補を表示する |
| 検索条件を解釈できない | 解釈できなかった条件を示し、追加質問を行う |
| クエスト詳細を生成できない | 元情報への参照と、取得できた範囲の情報を表示する |
| 理解度チェックを生成できない | 再試行を案内し、クエスト詳細の閲覧は継続できるようにする |
| 週間レポートのデータがない | 学習履歴がないことを示し、最初のクエスト検索を提案する |
| 一部の履歴を取得できない | 取得できた期間と項目を明示し、不完全な集計であることを表示する |
| 新規ユーザーで、クエストがまだない | クエストがないことを示し、チャットからクエストを探せることを案内する |
| 毎朝の自動更新に失敗した | 前回までのクエストを表示し、更新が遅れていることを示す |

## 12. 初期リリースの対象範囲

### 対象に含める機能

- 条件を指定したニュース検索
- 検索結果によるクエストボードの更新
- メイン領域内のクエスト詳細レイヤー
- クエストを対象としたチャット
- 単一選択式の理解度チェック
- 閲覧、初回回答、クリアの履歴記録
- チャット内の週間レポート
- 日別学習量の棒グラフ
- 週間レポートからの復習クエスト検索
- 毎朝のクエストの自動更新

### 対象に含めない機能

- 複数ユーザーでのランキング
- ユーザー同士のクエスト共有
- コメントやリアクション
- 外部SNSへの投稿
- 資格試験全体を対象とした学習管理
- ニュース本文の編集・公開
- 学習時間の厳密な計測
- ポイントやレベルに応じた報酬機能
